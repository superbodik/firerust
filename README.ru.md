# firerust

**Лёгкий браузерный движок, написанный на Rust с нуля.**

## О проекте

firerust — не форк Firefox или Chromium, а собственный движок: разбор HTML, каскад CSS, вёрстка, отрисовка и сеть — отдельные мелкие крейты. Из готовых библиотек взяты только низкоуровневые части: окно, шейпинг текста, декодирование картинок, математика flexbox.

Цель простая: открывать простые и средние по сложности сайты и тратить заметно меньше ОЗУ, чем Firefox на тех же страницах.

> Проект на ранней стадии. Пока это просмотрщик страниц, а не полноценный браузер. Сравнение по памяти с Firefox ещё не измерялось.

## Что работает сейчас

- Открывает локальный файл или адрес `http` / `https`
- Подтягивает и применяет CSS из `<style>`, `<link>` и `style=""` с настоящим каскадом: источник, специфичность, порядок, `!important`, наследование
- Блочная вёрстка: margin, padding, border, схлопывание отступов, `width`, `min-width`, `max-width`, `box-sizing`
- Строчный текст с переносом строк, разными цветами, весами, размерами и курсивом
- Картинки: PNG, JPEG, GIF, WebP
- Списки с маркерами
- Flexbox (через [taffy](https://github.com/DioxusLabs/taffy))
- Таблицы: ширины столбцов по содержимому, `colspan`
- Пересчёт вёрстки при изменении размера окна
- Навигация: адресная строка, кнопки назад / вперёд / обновить, клики по ссылкам, история с запоминанием позиции прокрутки
- Прокрутка колесом, стрелками, Page Up / Page Down, пробелом, Home и End, с ползунком справа
- Понятная страница ошибки, если страницу открыть не удалось
- Вкладки: открыть, закрыть, переключить; фоновые вкладки сверх двух последних использованных выгружают страницу из памяти и грузятся заново при выборе
- Общий кеш картинок с лимитом по байтам и панель памяти (`Ctrl+M`)
- Интерфейс: одна строка окна с вкладками в заголовке и свои кнопки окна, светлая и тёмная темы по настройке Windows (`FIRERUST_THEME=dark` или `light` задаёт принудительно), иконки [Bootstrap Icons](https://icons.getbootstrap.com/) (MIT), нарисованные векторными контурами, подсветка при наведении, значок замка или предупреждения и звезда закладки в адресной строке, страница меню `about:menu`
- Закладки: `Ctrl+D` добавляет или убирает закладку, `Ctrl+B` открывает список, `about:import` переносит закладки из Chrome, Edge, Brave, Vivaldi, Opera или из любого HTML-экспорта (в том числе из Firefox)
- Пароли: после входа внизу предлагается сохранить логин (`Ctrl+S`), при возвращении на сайт сохранённый логин подставляется в форму, `Ctrl+P` показывает список, `about:import-passwords` переносит их из CSV-экспорта Chrome, Edge, Firefox или Bitwarden; файл зашифрован ключом вашей учётной записи Windows
- Безопасность: страница из сети не читает локальные файлы и не ссылается на них, защищённая страница не грузит небезопасные картинки, стили и скрипты, а метатег `Content-Security-Policy` ограничивает источники скриптов, стилей и картинок
- Сеть: кодировки страниц (windows-1251, KOI8-R и остальные веб-кодировки), gzip и brotli, редиректы, cookies, запросы POST
- Формы: текстовые поля, пароли, флажки, радиокнопки, списки, `textarea` и кнопки, по которым можно кликать и в которые можно печатать, Tab между ними, отправка GET и POST, события `input`, `change` и `submit` для скриптов
- JavaScript на [Boa](https://github.com/boa-dev/boa): встроенные и внешние скрипты, `DOMContentLoaded` и `load`, `document` и элементы (запросы, создание и перенос узлов, `textContent`, `innerHTML`, атрибуты, `classList`, `style`), события с фазами захвата и всплытия, атрибуты и свойства `onclick`, `setTimeout`, `setInterval`, `requestAnimationFrame`, `console`, `localStorage`
- Ссылки всех видов: `#якорь` прокручивает без перезагрузки, `target="_blank"`, Ctrl+клик и средний клик открывают новую вкладку, `mailto:` и `tel:` уходят системе (только поля письма), внизу видно, куда ведёт ссылка под курсором, кликабельны целые блочные ссылки и картинки внутри ссылок, а `location.href`, `location.assign` и `window.open` работают из скриптов
- Файлы: текст, JSON, XML и CSS открываются читаемой страницей, PNG / JPEG / GIF / WebP как картинка, всё остальное (архивы, PDF, `Content-Disposition: attachment`) сохраняется в папку «Загрузки»
- Больше CSS: `border-radius`, `text-decoration`, `accent-color`, переменные `var()`, `@media` (для окна рабочего стола), `@supports`, `@layer`, атрибутные селекторы, `:not()`, `:nth-child()`, `:first-child`, `:link`, `:root` и соседние комбинаторы
- `about:settings` (тема, где лежат файлы) и `about:console` (что печатали скрипты и какие упали)
- Большие страницы строятся быстро: статья Wikipedia занимает четверть секунды в релизной сборке
- Глубокая вложенность безопасна: вёрстка идёт на большом стеке, дерево освобождается итеративно

Страницы, которые хорошо загружаются и раскладываются: Hacker News, example.com, CERN, NPR, Lobsters, сайты с документацией. Страницы, где нужны `float`, `position` или сетка CSS (Wikipedia, rust-lang.org), открываются, но выглядят сломанными.

Клавиши: `Ctrl+L` или `F6` — фокус на адресную строку, `Enter` — открыть, `Esc` — отмена, `Alt+Left` и `Alt+Right` — назад и вперёд, `F5` или `Ctrl+R` — обновить, `Ctrl+T` — новая вкладка, `Ctrl+W` — закрыть, `Ctrl+Tab` и `Ctrl+Shift+Tab` — переключение вкладок, `Ctrl+M` — панель памяти, `Ctrl+Плюс`, `Ctrl+Минус`, `Ctrl+0` и `Ctrl+колесо` — масштаб страницы (25–500%, запоминается по сайту). Сочетания работают по физическим клавишам, поэтому подходят для любой раскладки.

## Быстрый старт

Нужно: Rust 1.96 (тулчейн MSVC), Windows 11.

```
git clone https://github.com/superbodik/firerust.git
cd firerust
cargo run -p fr-shell -- tests/pages/blog.html
```

Небольшой связанный сайт, чтобы попробовать навигацию:

```
cargo run -p fr-shell -- tests/pages/site/index.html
```

Демонстрации JavaScript, счётчик с таймером и выпадающее меню:

```
cargo run -p fr-shell -- tests/pages/js_counter.html
cargo run -p fr-shell -- tests/pages/js_menu.html
```

Формы и вход на сайт через встроенный тестовый сервер (во втором терминале `cargo run -p fr-test-server`, потом `http://127.0.0.1:8080/login`, логин `ada`, пароль `lovelace`):

```
cargo run -p fr-test-server -- 127.0.0.1:8080
cargo run -p fr-shell -- tests/pages/forms.html
```

Адрес тоже подойдёт, а несколько адресов откроются вкладками:

```
cargo run -p fr-shell -- https://example.com
cargo run -p fr-shell -- tests/pages/plain.html tests/pages/blog.html
```

Тестовые страницы лежат в [tests/pages](tests/pages): `plain`, `nested`, `entities`, `cyrillic`, `blog`, `images`, `columns`, `tables` и связанный `site/`.

## Память

Главная цель проекта. Первые замеры на Windows 11, release-сборка, против Firefox со свежим временным профилем (приватный рабочий набор, сумма по всем процессам браузера):

| Случай | firerust | Firefox |
|---|---|---|
| Одна простая страница | 5,6–6,7 МБ, 1 процесс | 310–350 МБ, 11 процессов |
| Одна страница со скриптами (счётчик, меню) | 7,5 МБ, 1 процесс | 325–330 МБ, 11 процессов |
| 8 вкладок, скрипты выполняются (локальные страницы, example.com, Hacker News, lobste.rs, rust-lang.org) | 16,8 МБ, 1 процесс | 420–590 МБ, 15 процессов |

Сравнение пока неравное: у firerust поддержана лишь малая часть веб-платформы (нет `fetch`, нет размеров элементов для скриптов), только часть HTML и CSS, нет веб-шрифтов и медиа, поэтому цифры — нижняя граница, и они вырастут вместе с возможностями. Сам движок скриптов стоит около 2 МБ на страницу, где он нужен. Скрипт замера: [tools/mem-bench/mem-bench.ps1](tools/mem-bench/mem-bench.ps1).

## Архитектура

У каждого крейта одна ответственность. В каждом файле один тип или одна функция.

```
fr-shell ─ бинарник: точка входа и сцены
 ├─ fr-window   окно (winit), события ввода, вывод кадра (softbuffer)
 ├─ fr-ui       прокрутка, поле адреса, геометрия панели (без окна)
 ├─ fr-icons     иконки Bootstrap Icons как векторные контуры
 ├─ fr-theme     светлая и тёмная палитры и стили страниц
 ├─ fr-bookmarks список закладок, файл и импорт из других браузеров
 ├─ fr-passwords сохранённые логины в зашифрованном файле, импорт CSV
 ├─ fr-download имя файла и сохранение скачанного
 ├─ fr-settings  выбор темы и файл настроек
 ├─ fr-dpapi    обёртка над Windows DPAPI, единственный крейт с unsafe
 ├─ fr-security правила безопасности страницы: смешанный контент, локальные файлы, политика содержимого
 ├─ fr-js       движок JavaScript на Boa: DOM, события, таймеры
 ├─ fr-form     поля форм, запросы GET и POST, порядок фокуса
 ├─ fr-tab      вкладки, выгрузка фоновых, оценки памяти
 ├─ fr-history  стек назад / вперёд с позициями прокрутки
 ├─ fr-cache    LRU-кеш с лимитом по байтам
 ├─ fr-mem      память текущего процесса
 ├─ fr-page     адрес → загрузка → разбор → стили → картинки
 │   ├─ fr-net     разбор адреса, загрузка file / http / https
 │   ├─ fr-html    HTML → DOM (html5ever)
 │   ├─ fr-css     разбор, селекторы, каскад, вычисленные стили
 │   └─ fr-image   декодирование PNG / JPEG / GIF / WebP
 ├─ fr-layout   дерево боксов: блоки, текст, картинки, flex, таблицы, поиск под курсором
 ├─ fr-paint    список команд отрисовки и рисование
 ├─ fr-raster   холст (tiny-skia) и экспорт пикселей
 ├─ fr-text     шрифты и шейпинг текста (cosmic-text)
 ├─ fr-dom      DOM-дерево на арене, обход без рекурсии
 └─ fr-geom     Point, Size, Rect, Rgba
```

Решения, которые работают на цель по памяти:

- DOM лежит в одной арене: узлы в одном `Vec`, связи через 4-байтовые `NodeId`
- Обход и освобождение итеративные, без рекурсии по глубине документа
- Вычисленные стили и боксы вёрстки — плоские компактные данные

## Разработка

```
cargo build --workspace
cargo test --workspace
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
```

Проходит около 880 тестов. Один сетевой тест запускается вручную:

```
cargo test -p fr-page --test real_sites -- --ignored
```

Правила кода: без комментариев, мелкие файлы по папкам, без `unwrap` и `expect` в библиотечном коде, без `unsafe` без отдельного решения.

## Известные ограничения

- У закладок в интерфейсе только заголовки папок, поиска нет; закладки Firefox берутся только из его HTML-экспорта; пароли импортируются только из CSV, прямого чтения из профилей Chrome и Edge нет (они в SQLite и привязаны к ключу самого браузера), а сохранённые пароли лежат в памяти без шифрования, пока браузер работает
- Политика содержимого читается только из метатега, не из заголовков ответа; nonce и хеши не поддержаны
- Поля форм занимают отдельную строку, список меняется по клику без выпадающего окна, нет загрузки файлов, кнопки `reset` и проверки полей; cookies живут только в памяти; возврат после POST снова запрашивает адрес методом GET
- Скрипты и итоговая сборка страницы идут в потоке окна, поэтому тяжёлая страница может подвесить окно, пока собирается; адреса запуска после первого грузятся по очереди
- Масштаб страницы растягивает рисунок: тонкие рамки при дробном масштабе могут быть мягкими
- Назад и вперёд загружают страницу заново, кеша страниц пока нет
- Последнюю вкладку закрыть нельзя
- Строчная картинка становится отдельным блоком; отступы, рамки и padding у строчных элементов игнорируются
- Нет `float`, `position`, `grid`, `overflow`, `opacity`, `calc()`, веб-шрифтов, `::before` и `::after`; `@media` считается для условного окна рабочего стола, а не для настоящего; у картинок пока нет скруглённых углов
- Скачивание идёт через память (до 256 МиБ) и не показывает ход; атрибут `download` не используется
- В таблицах нет `valign` и `border-spacing`
- JavaScript: нет `fetch` и `XMLHttpRequest`, нет `document.write`, скрипты не видят размеров элементов, до страниц доходят только клики и таймеры (нет событий наведения и клавиатуры), после каждого изменения заново стилизуется весь документ
